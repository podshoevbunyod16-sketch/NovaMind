# Модернизация интерфейса и настоящая озвучка ответов

Отчёт по задаче: раскрывающиеся разделы настроек, единый переключатель языка,
кнопка «Озвучить» в поле ввода и у каждого ответа ИИ, серверный TTS с
настоящими провайдерами, очередью, отменой и автоозвучкой.

Всё, что описано ниже, подключено к реальной логике: кнопок-заглушек,
демо-анимаций и «понарошку» сохранённых настроек в коде нет.

---

## 1. Что реализовано

**Раскрывающиеся разделы (единый компонент `static/accordion.js`)**

- Один компонент на всю страницу настроек: `<section class="acc"
  data-accordion="KEY">` + кнопка шапки `[data-accordion-toggle]` + панель
  `[data-accordion-panel]`. Второй, конкурирующей реализации нет.
- Доступность: `aria-expanded`, `aria-controls` (панель получает `id`
  автоматически), `aria-hidden` не дублируется — панель просто получает
  `hidden`; шапка реагирует на клавиши Enter и пробел.
- Состояние хранится в `localStorage` (`nova_accordion_state`) и
  восстанавливается после перезагрузки; ссылки в навигации настроек
  открывают нужный раздел, а не просто прыгают по якорю.
- Анимация — только `transform`/`opacity` (дешёво на слабых телефонах), при
  `prefers-reduced-motion` отключается.
- Содержимое **не перерисовывается** при открытии/закрытии: повторное
  открытие не плодит дубликаты DOM и не теряет уже загруженные данные.

Разделы (в этом порядке): **Провайдеры**, **MCP-серверы**, **Скиллы**,
**Медиа-модели**, **Поиск в интернете**, **Озвучка**, **Язык интерфейса**
(последним, как требовалось).

- **Провайдеры** — живой список провайдеров и моделей с сервера
  (`/api/settings/providers`, `/api/settings/models`). У каждого провайдера
  своя кнопка «Проверить»: она запрашивает каталог заново
  (`GET /api/settings/models?provider=<id>&refresh=1`) и показывает либо
  «Каталог доступен · моделей: N», либо дословную ошибку провайдера
  («Groq: HTTP 401 — ключ не принят»). Никаких выдуманных статусов.
- **MCP-серверы** — реальный реестр `mcp_registry`: имя, транспорт
  (`HTTP (Streamable)` / `SSE`), статус, авторизация, инструменты,
  время последней проверки и текст последней ошибки; подключение — только по
  кнопке, с проверкой `initialize` на сервере; инструменты подгружаются
  отдельной кнопкой (`tools/list`); секрет вводится в скрытое поле.
- **Скиллы** — отдельная категория (это инструкции `SKILL.md`, а не
  MCP-серверы): имя, описание, доступность, требуемые инструменты, включение
  и выключение (`POST /api/settings/skills/<id>/enabled`), подробности,
  удаление, ZIP и текст. Выключенный скилл остаётся на диске, но не попадает
  в промпт агента — разрешения по-прежнему проверяют агент и MCP-политика.
- **Озвучка** — статус TTS-провайдера, переключатель автоозвучки, выбор
  провайдера/голоса/языка, «читать код», «Прослушать пример» и «Остановить».
- **Язык** — ru / en / tg (то, что уже поддерживалось).

**Переключение языка (`static/i18n.js`)**

- Добавлено около 90 новых записей ru/tg/en и шаблоны с числами: названия и
  подписи разделов, состояния кнопок озвучки, ошибки TTS, панель MCP,
  скиллы, проверка провайдера, «Озвучиваю часть N из M…».
- Язык применяется сразу при нажатии (не только после перезагрузки), затем
  сохраняется на сервере (`POST /api/settings/lang`) и в `localStorage`.
- Переводятся подписи, подсказки, плейсхолдеры, `aria-label`, `title`,
  уведомления, состояния загрузки и элементы управления озвучкой.
  **Сообщения пользователя и ответы ИИ никогда не переводятся.**

**Кнопки озвучки**

- Кнопка «Озвучить» в поле ввода рядом с микрофоном (`#btn-speak`):
  неактивна, пока нет ответа; во время воспроизведения превращается в
  «Стоп», на паузе — в «Продолжить».
- У каждого ответа ИИ — своя кнопка в блоке действий; она озвучивает
  **именно этот ответ**, а не последний в чате.
- Состояния: `idle` → `loading` («Готовлю аудио…») → `playing` → `paused` →
  `idle`; отдельно `error` и `fallback` (браузерный синтез). Иконка и
  подсказка меняются вместе с состоянием; после конца воспроизведения кнопка
  сама возвращается в ожидание.
- Пока текст ещё стримится, кнопка ответа не появляется; кнопка в поле ввода
  остаётся привязанной к последнему завершённому ответу.

**Озвучка**

- Реальные провайдеры по приоритету: уже подключённый TTS → бесплатные /
  условно-бесплатные сервисы → свой endpoint.
- Длинный текст режется по границам предложений (и только в крайнем случае —
  по словам, никогда посреди слова); части играют по очереди, пока сервер
  генерирует следующие.
- Повтор при явно временных ошибках (таймаут, 429, 5xx, сеть), таймауты,
  понятные тексты ошибок.
- Файлы складываются в существующий каталог медиа (`generated_media/` через
  `media_generation.save_media`) и отдаются по `/media/<file>`; старые файлы
  озвучки убираются по TTL. **В `localStorage` аудио не попадает** — там
  лежит только копия настроек на случай недоступного сервера.
- Ключи API в браузер не передаются: клиент отправляет только текст и
  параметры голоса.

**Остановка и очередь**

- «Стоп» прерывает воспроизведение **и** незавершённый запрос
  (`AbortController`), дополнительно сообщает серверу `POST /api/tts/cancel`
  по `job_id`; запоздавшие события отменённого запуска игнорируются
  (счётчик поколений), поэтому поздний ответ не запускает звук заново.
- Один активный запуск на вкладку: новая озвучка останавливает предыдущую.
- Остановка озвучки не касается генерации текста: `Linux.activeAbort` не
  трогается (проверено тестом).
- Смена/очистка диалога и выход останавливают озвучку и очищают очередь.

**Автоозвучка**

- Переключатель «Автоматически озвучивать ответы ИИ» в настройках с явными
  состояниями «Включено»/«Выключено»; значение живёт на сервере
  (`runtime_settings.json`, ключ `speech`), у гостя — в `localStorage`.
- Ровно одна авто-озвучка на завершённый ответ (защита `WeakSet` +
  проверка «остановлено/ошибка/пусто»). Не озвучиваются: сообщения
  пользователя, пустые ответы, остановленные и упавшие генерации, старые
  сообщения после перезагрузки страницы.
- Выключение автоозвучки во время авто-воспроизведения гасит его и отменяет
  запрос, но **не убивает ручное** воспроизведение.

**Подготовка текста**

- Отдельная функция `tts_service.speech_text()`: снимает Markdown (`#`, `**`,
  списки, цитаты, таблицы → строки, inline-код), ссылки заменяет на слово
  «ссылка», блоки кода по умолчанию пропускает (есть переключатель
  «Читать вслух блоки кода»). Исходное сообщение не изменяется — в чате
  остаётся прежний Markdown.

## 3. Как работает озвучка

1. **Кнопка.** Пользователь жмёт «Озвучить» у ответа или под полем ввода.
   Клиент берёт текст именно этого ответа (Markdown, как в чате) и вызывает
   `POST /api/tts/speech`.
2. **Сервер.** `routes/tts.py` проверяет вход (непустой текст, лимит длины
   `TTS_MAX_CHARS`, лимит частоты `TTS_RATE_LIMIT`), убирает устаревшие файлы
   и запускает `tts_service.synthesize()`.
3. **Выбор провайдера.** `resolve_model()` идёт по приоритету: явно выбранный
   провайдер → первый доступный по ключам (Google AI Studio → Groq PlayAI →
   Pollinations → свой `AUDIO_TTS_URL`). Если не настроен никто, сервер честно
   отвечает событием `error` с `mode: "browser"`.
4. **Подготовка текста.** `speech_text()` снимает Markdown, заменяет ссылки
   словом «ссылка», таблицы читает построчно, блоки кода пропускает (если не
   включено «читать код»). Исходное сообщение не меняется.
5. **Нарезка.** `split_text()` делит текст по границам предложений до
   `TTS_CHUNK_CHARS` (900 по умолчанию), не разрывая слов; максимум
   `TTS_MAX_CHUNKS` частей.
6. **Синтез.** Каждая часть уходит в `media_generation.generate_media()`
   (тот же слой, что рисует картинки: единые ключи, таймауты, сохранение в
   `generated_media/`). Временные ошибки повторяются один раз; постоянные
   (400/401/403) — нет. Результат, который не является аудио, не играет.
7. **Поток ответа.** Сервер отвечает NDJSON: `start` (job_id, провайдер,
   голос, число частей) → `chunk` (url, mime, текст части) → `done` или
   `error`. Клиент играет первую часть сразу, следующие — по мере прихода,
   без «склейки» всего файла.
8. **Плеер.** Один `Audio` на часть; состояние пишется в `data-speech-state`
   кнопки и в подпись, после последней части кнопка возвращается в `idle`.
   Все части одного ответа идут строго по порядку; одновременно звучит не
   больше одного запуска.
9. **Стоп.** `NovaSpeech.stop()` увеличивает счётчик поколений, прерывает
   `fetch` через `AbortController`, останавливает текущий `Audio`, чистит
   очередь и отправляет `POST /api/tts/cancel`. Всё, что придёт от старого
   запроса, отбрасывается по счётчику поколений.
10. **Автоозвучка.** После завершения ответа `app.js` вызывает
    `NovaSpeech.onTurnFinished(element, text, {stopped})`; контроллер сам
    проверяет настройку, пустоту текста, флаг остановки и то, что этот ответ
    ещё не озвучивался.
11. **Резерв.** Если серверного провайдера нет, а браузер умеет
    `speechSynthesis`, кнопка переходит в состояние `fallback` («Браузерная
    озвучка») и в подсказке прямо сказано, что это резерв, а не голос модели.

- язык: три языка, активный подсвечен, сохранение в `localStorage`, перевод
  заголовка/разделов/переключателя, запрос на сервер;
- чат: кнопка в поле ввода и у каждого ответа, ручная озвучка именно своего
  ответа, состояния `loading`/`playing`/`paused`/`idle`, переход ко второй
  части после первой, пауза и продолжение, автоозвучка ровно один раз и без
  дублей, выключение автоозвучки гасит авто, но не ручную, стоп отменяет
  запрос и не трогает генерацию текста, один голос за раз, смена диалога
  останавливает озвучку, пустой/остановленный ответ не озвучивается.

**Честно о реальном звуке.** В этой среде нет ключей TTS-провайдеров, поэтому
**живая генерация аудио у внешнего провайдера не проверялась**. Проверено:
реальная HTTP-раздача NDJSON, реальная запись файлов в каталог медиа и их
выдача по `/media/<file>`, обработка ошибок и отмена — но сам вызов
`generate_media` в тестах подменён (сеть недоступна). Браузерный резерв
(`speechSynthesis`) в jsdom тоже заглушён, то есть его звучание не проверялось.
Первый настоящий прогон нужно сделать после добавления ключа — как это
сделать, см. раздел 5.

## 5. Что настроить

1. Добавить ключ хотя бы одного TTS-провайдера в `.env` и перезапустить
   сервер:

   ```env
   # бесплатный тариф с лимитами, 28 голосов, ru + en
   GEMINI_API_KEY=...
   # или бесплатный Groq PlayAI (голоса только английские)
   # GROQ_API_KEY=...
   # или Pollinations (нужен ключ, иначе синтез не работает)
   # POLLINATIONS_API_KEY=...
   # или свой OpenAI-совместимый endpoint
   # AUDIO_TTS_URL=https://api.openai.com/v1/audio/speech
   # AUDIO_TTS_MODEL=tts-1
   # AUDIO_API_KEY=...
   ```

2. Открыть `/settings` → раздел **Озвучка** → «Проверить». Должно появиться
   «Озвучка готова: <провайдер> · <модель>», а в списке голосов — реальные
   голоса этого провайдера.
3. Выбрать голос и язык, нажать «Прослушать пример» — это настоящий запрос
   синтеза. Затем при желании включить «Автоматически озвучивать ответы ИИ».
4. При необходимости подкрутить лимиты и размеры (все переменные описаны в
   `.env.example`): `TTS_MAX_CHARS`, `TTS_CHUNK_CHARS`, `TTS_MAX_CHUNKS`,
   `TTS_TIMEOUT`, `TTS_FILE_TTL`, `TTS_FILE_KEEP`, `TTS_RATE_LIMIT`,
   `TTS_RATE_USER`, `TTS_RATE_GUEST`, `TTS_RATE_WINDOW`.
5. Ничего не настраивать в браузере не нужно: ключи живут только на сервере.

## 6. Известные ограничения

- **Живой звук не подтверждён** в этой среде (нет ключей провайдеров) — см.
  раздел 4. Это единственный пункт, который нельзя закрыть тестами без ключа.
- **Groq PlayAI** отдаёт только английские голоса (`languages: ["en"]` в
  каталоге). Русский текст он прочитает с сильным акцентом или ошибкой;
  сервер не подменяет выбранный голос автоматически. Для русского текста
  выбирайте Google AI Studio — у него голоса помечены `ru` и `en`.
- **Пауза** работает для серверного аудио (обычный `<audio>`), но не для
  браузерного резерва: у `speechSynthesis` пауза зависит от платформы.
- **Между частями** возможна микропауза: части синтезируются и играются по
  очереди, а не склеиваются в один файл (так первая часть звучит раньше).
  Если провайдер медленный, стык слышен.
- **Текст ошибок провайдера** приходит с сервера по-русски и не переводится
  при смене языка интерфейса: это диагностика, а не подпись элемента.
- **Автоозвучка** намеренно не срабатывает для ответов, восстановленных из
  истории, и для ответов, которые были остановлены или завершились ошибкой.
- **Браузерный резерв** честно помечен («Браузерная озвучка»), но его голос
  и качество зависят от устройства и установленных голосов ОС.
- **Отмена на сервере** — best-effort: сервер проверяет флаг между частями и
  не прерывает уже отправленный HTTP-запрос к провайдеру (у большинства
  провайдеров нет API отмены), поэтому одна часть может досинтезироваться
  впустую. Пользователь при этом ничего не слышит.
- **Файлы озвучки** удаляются по TTL при следующих запросах синтеза, а не по
  таймеру; на очень тихом сервере старые файлы могут полежать дольше TTL.
- Страница настроек по-прежнему требует JS: без него аккордеоны не
  раскрываются (панели помечены `hidden`), но это поведение было и раньше.
