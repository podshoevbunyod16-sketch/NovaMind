# NovaMind: единый оркестратор и сравнение с Arena Agent Mode

Проверено по публичным материалам 25 октября 2026 года. Это независимая
реализация наблюдаемого принципа, не копия закрытого кода Arena.

## Что подтверждают официальные источники

- https://help.arena.ai/articles/5432423882-how-to-use-agent-mode — модель-
  оркестратор выбирает инструменты; многошаговая работа, поиск, файлы, изображения,
  sandbox/Bash, уточняющие вопросы, скачивание workspace.
- https://arena.ai/blog/agent-mode — автономное планирование и выполнение
  многошагового workflow с тестированием и итерациями в sandbox.
- https://help.arena.ai/articles/1655691990-how-to-use-coding-in-agent-mode —
  GitHub-авторизация, выбор разрешённых репозиториев, отдельная копия в sandbox,
  diff review, clone/commit/push/PR и preview.

Документация не раскрывает внутренний orchestration-код, точные system prompts,
формат событий, устройство изоляции, управление процессами и credentials.
Нельзя выдавать предположения о них за установленный факт.

## Что изменено в NovaMind

По умолчанию `AGENTICSEEK_EXECUTION_MODE=unified`:

1. Один `OrchestratorAgent` владеет задачей и историей наблюдений.
2. Модель выбирает из инструментов, реально доступных текущему запуску.
3. Движок выполняет вызов через прежний слой permissions/confirmation.
4. Результат возвращается модели; она исправляет ошибку или выбирает следующий шаг.
5. Завершение — ответ с результатами, проверками, путями и ограничениями.

Не нужно угадывать специалиста по ключевым словам или передавать смешанную
задачу web → files → coder. Используется существующий провайдер моделей;
инструменты, таймлайн, сохранение run/steps, отмена и дедлайн сохранены.
Исчерпание бюджета явно останавливает исполнителя. Простые приветствия остаются
безопасным разговорным маршрутом, где код в ответе не запускается.

В этом проекте протокол инструментов остаётся fenced-блоками, не native tool
calling API Arena. `nova …` из предыдущей доработки остаётся альтернативным
командным интерфейсом. Arena публично описывает отдельные инструменты, а не
требование исполнять все функции только через Python/Bash.

## Совместимость и ограничения

- `AGENTICSEEK_EXECUTION_MODE=specialists` возвращает прежнюю архитектуру.
- `force_role`, строгий MCP и профиль `coding` сохраняют прежние более узкие
  границы. Веб-специалист не получает shell.
- Без workspace оркестратор не получает файловые инструменты, Python и терминал.
- MCP/медиа/память доступны лишь при наличии callbacks и настроек.
- Локальный демонстрационный режим не становится полноценной языковой моделью.
- Полный Bash, отдельные OS-контейнеры на пользователя, OAuth GitHub, новый diff
  panel, управление долгоживущими процессами/preview и интерактивные формы
  уточнений в этой доработке НЕ реализованы. Это отдельные инфраструктурные задачи.
- Существующий terminal runner — ограниченный исполнитель, не доказанная
  изоляция произвольного Python-кода. Для недоверенных задач требуется внешняя
  изоляция ОС без секретов и с отдельными ресурсными/сетевыми лимитами.
- Агент не получает прав администратора GitHub автоматически. Push зависит от
  фактической авторизации, подтверждения и разрешённых команд runner.

## Проверка

`tests/test_orchestrator.py`: единый исполнитель, доступность инструментов,
workspace, сохранение явного веб-маршрута, legacy-переключатель, возврат результатов
поиска модели до следующего ответа. Тесты используют подставную модель, не
доказывают качество конкретного внешнего LLM или доступность внешних сервисов.
