# Повторный аудит структуры NovaMind (2026-10-27)

Проверка после исправления агентного режима. Цель — ответить на два вопроса:

1. **Почему в ответе отображается мало текста, хотя он должен быть длиннее?**
2. **Чего не хватает в структуре проекта** по семи направлениям из таблицы
   (безопасность ×2, знания, наблюдаемость, качество, эксплуатация,
   архитектура).

Проверялось по фактическому дереву репозитория, а не по документации:
`app.py`, `config.py`, `ai_providers.py`, `local_llm.py`, `identity.py`,
`security.py`, `memory.py`, `skills_registry.py`, `mcp_registry.py`,
`database.py`, `usage_stats.py`, `routes/*`, `agenticseek/*`, `static/*`,
`tests/*`, `evals/*`, `.github/workflows/*`.

## 1. Почему ответ был коротким (найдено и исправлено)

### Причинно-следственная цепочка

| # | Где | Что происходило |
|---|-----|-----------------|
| 1 | `agenticseek/engine.py` | Один ответ модели был жёстко ограничен `int(1200 * AGENTICSEEK_SPEED)` токенов. Обычный чат при этом брал `max_tokens` провайдера — 8192…32768 (`config.PROVIDERS`). |
| 2 | провайдер | Длинный ответ упирался в 1200 токенов и **обрывался на полуслове** (`, а в конце … и`). |
| 3 | `routes/agent.py::final_answer_text` → `_looks_complete_answer` | Такой текст считался «незаконченным черновиком» (последнее слово служебное, запятая, незакрытая кавычка) и **отбрасывался целиком** — возвращалась пустая строка. Проверка не различала короткий обрывок-рассуждение и длинный ответ в 2000+ символов. |
| 4 | `agenticseek/engine.py::_recover_answer` | Движок просил «чистый ответ» через `CLEAN_ANSWER_SYSTEM`, но с тем же потолком 1200; промпт к тому же содержал «скажи это одной короткой фразой». |
| 5 | `salvage_quoted_answer` / финал | Цитаты для спасения не было, поэтому пользователь получал одну строку: `Не удалось получить ответ. Причина: Агент не вернул ответ.` |

Воспроизводилось тестом: длинный ответ модели, заканчивающийся на `… и`,
давал **58 символов вместо 2069**. Дополнительные укоротители:
`casual_agent.txt` («отвечай … коротко»), `browser_agent.txt`
(«короткий ответ по задаче»), `_fallback_answer(max_tokens=800)`,
`_answer_from_observation` («списком из 3–5 пунктов, 1 строка»),
а также `strip_leaked_reasoning`, который оставлял только непрерывный хвост
русских абзацев — ответ, заканчивавшийся кодом, терялся.

### Что исправлено

* **`AGENT_MAX_TOKENS`** (по умолчанию 4096, диапазон 1024–32768). Роут
  (`routes/agent.py`, `routes/coding_agent.py`) дополнительно ограничивает его
  `max_tokens` выбранного провайдера и передаёт в `EngineContext.max_tokens`.
  `AGENTICSEEK_SPEED` теперь может только укоротить бюджет, но не превысить
  лимит провайдера.
* **`repair_truncated_answer()`** различает короткий обрывок (утечка
  рассуждений — выбрасываем) и длинный ответ, оборванный на лимите (оставляем
  завершённую часть до последнего полного предложения).
* **`AgentEngine._continue_answer()`** просит модель дописать только хвост
  (`CONTINUE_ANSWER_SYSTEM`), убирает повтор через `_drop_overlap()` и склеивает
  части. Если продолжить не удалось, пользователь всё равно видит ~2000
  символов, а не строку ошибки. В чате виден шаг «дописываю до конца».
* **`_looks_complete_answer()`** маскирует fenced-блоки кода: непарные кавычки
  внутри кода больше не считаются обрывом; незакрытый ``` определяется явно.
* **`strip_leaked_reasoning()`** убирает только абзацы-рассуждения, а не «хвост
  русских абзацев»: код, списки и латиница в конце ответа сохраняются.
* **Промпты** `casual_agent`, `browser_agent`, `orchestrator_agent`,
  `CLEAN_ANSWER_SYSTEM` и инструкции поиска теперь просят полный, законченный
  ответ. `_fallback_answer()` использует общий бюджет токенов.
* **Офлайн-контур** `local_llm.py` отвечает на вопросы про структуру проекта
  развёрнутым описанием каталогов (2391 символ в живой проверке вместо
  короткой заглушки). Без ключа провайдера длинных произвольных ответов быть
  не может — это ограничение демо-режима, а не баг.

Регрессия закрыта `tests/test_answer_length.py` (17 тестов) и разделом 21
`tests/frontend/smoke.mjs` (длинный ответ целиком в пузыре чата).

| `agenticseek/` | движок: `engine.py`, `router.py`, `timeline.py`, `policy.py`, `state.py`, `offline.py`, `core/` (агенты и цикл), `tools/` (терминал/Python/файлы/веб/MCP), `providers/`, `prompts/base/*.txt` |

## 3. Аудит по семи направлениям

Легенда: **есть** — реализовано и покрыто тестами; **частично** — есть
разрозненные механизмы без единого контракта; **нет** — компонента нет.

| Область | Ключевой компонент (приоритет) | Статус | Что есть сейчас | Чего не хватает |
|---|---|---|---|---|
| Безопасность | Инфраструктурные Guardrails: контроль ввода/вывода, прав инструментов (🔴) | **частично** | `agenticseek/policy.py`: `risk_of`, `needs_confirmation`, `redact`, `wrap_untrusted`; `routes/terminal.py`: allow-list из 141 команды, `safe_path`; `security.py`: rate-limits; `evals/tasks/safety.yaml` | Единого слоя guardrails нет: проверка входа на инъекции/секреты/размер размазана по роутам; выход не проверяется на утечку ключей/PII; нет централизованной матрицы «кто какой инструмент может звать» и аудита отказов |
| Безопасность | Криптографическая идентичность и least-privilege для инструментов (🔴) | **частично** | `identity.py`: владелец из подписанной cookie, `workspace_for` (sha256-директория); `security.INTERNAL_RUN_TOKEN`; `mcp_registry` проверяет права на уровне роутов | Нет подписанных (HMAC) грантов на инструменты с TTL и scope; `contextvars` владелец не криптографически связан с вызовом инструмента; нет разделения read/write/danger на уровне токена; нет ротации ключа подписи |
| Знания | RAG-пайплайн для внутренних документов и баз знаний (🟠) | **нет** | `memory.py` (факты пользователя), `skills_registry.py` (Markdown-навыки в промпт), `docs/*.md`, `notes/research/*`, поиск по вебу `routes/search.py` | Нет индексации/чанкинга/эмбеддингов, нет гибридного поиска по `docs/` и коду, нет цитирования источников в ответе; знания не версионируются |
| Наблюдаемость | Сквозная трассировка всех шагов агента (🟠) | **частично** | `agent_runs` + `agent_run_steps` + `step_traces`, `usage_stats` (токены/стоимость), заголовок `X-Agent-Run-Id`, структурированные логи | Нет единого `trace_id/span_id` и parent/child связей между «понимание → получение инструментов → шаг → модель → ответ»; нет экспорта (OTLP/JSON), нет корреляции запроса БД/сети/модели, нет дашборда и алертов |
| Качество | Непрерывная оценка (Evals) и регрессионное тестирование (🟠) | **частично** | `evals/run.py` + `runner.py` + 25 YAML-задач; 751 pytest-тест; 4 CI-workflow (tests, smoke, coding-agent, groq-provider) | Evals не запускаются в CI, нет порога успеха/сравнения с baseline, нет ночных прогонов и отчёта-артефакта; нет метрик качества ответа (длина, полнота, галлюцинации). Именно поэтому баг с коротким ответом не ловился |
| Эксплуатация | Управление промптами: версионирование и жизненный цикл (🟡) | **нет** | Промпты — статичные `agenticseek/prompts/base/*.txt`, загружаются `prompt_path()`; часть инструкций зашита строками в `engine.py` и `routes/agent.py` | Нет реестра версий/хешей/автора/даты, нет A/B и отката, нет проверки «промпт изменился → перегони evals», нет единого места для system-инструкций (сейчас «коротко» жило в txt, а `CLEAN_ANSWER_SYSTEM` — в коде) |
| Архитектура | Паттерны мультиагентной оркестрации (🟡) | **частично** | `router.py` (выбор роли), `planner_agent.py` (JSON-план с зависимостями), `orchestrator_agent.py` (единый исполнитель), специалисты code/file/web/casual/project, передача хода `_tool_agent` | Нет явных паттернов supervisor/debate/critique/map-reduce, нет общего бюджета и разделяемой памяти между агентами, нет повторного планирования после провала шага, нет метрик «кто сколько внёс» |

### Связь аудита с багом короткого ответа

Баг возник на стыке трёх пробелов: **Качество** (не было eval-задачи на
длинный ответ), **Наблюдаемость** (не было спана «ответ модели упёрся в
max_tokens»), **Эксплуатация** (инструкция «коротко» и лимит 1200 жили в
разных местах без версионирования). Первый шаг закрытия — регрессионные
тесты и трассировка лимитов; они уже добавлены.

## 4. Приоритетный план (что делать дальше)

1. 🔴 **Guardrails** — модуль `agenticseek/guardrails.py`: единый вход
   (`check_input`: длина, инъекции, секреты), выход (`check_output`: ключи,
   PII, запрещённый контент), матрица прав инструментов; вызвать до/после
   `AgentEngine` и в `routes/terminal.py`.
2. 🔴 **Идентичность инструментов** — `tool_grants.py`: HMAC-подписанный
   grant (owner, run_id, tool, scope, TTL), проверка в `Agent.run_tool`;
   ротация ключа через `.env`.
3. 🟠 **Трассировка** — `tracing.py`: trace_id/span_id, parent, тайминги,
   запись в `agent_run_steps` + экспорт OTLP/JSON; корреляция с `run_id`.
4. 🟠 **Evals в CI** — workflow `evals.yml`, baseline-отчёт, порог успеха,
   артефакт с графиком; добавить категорию `answer_quality` (длина/полнота).
5. 🟠 **RAG** — `knowledge/`: чанкинг `docs/` + SQLite FTS5 + опциональные
   эмбеддинги, инструмент `knowledge_search`, цитирование в ответе.
6. 🟡 **Реестр промптов** — `prompt_registry.py`: версия/хеш/метаданные,
   загрузка по id, CLI для diff и отката; перевести строки из кода в реестр.
7. 🟡 **Оркестрация** — описать и реализовать паттерны supervisor/critique,
   общий бюджет и разделяемую память агентов.
