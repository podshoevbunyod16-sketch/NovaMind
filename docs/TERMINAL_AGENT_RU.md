# Командный интерфейс агента

## Выключатель инструментов

Кнопка «Автопоиск» в чате — главный выключатель всех инструментов агента:

* **включена** — доступны `terminal`, `python`, файлы, веб-поиск, MCP, медиа и
  память; агент выполняет шаги через терминал песочницы;
* **выключена** — движок не создаёт ни одного инструмента (`tools_allowed=False`).
  Роутер выбирает единственного безоружного собеседника и отправляет запрос в
  ИИ-модель один раз; ответ возвращается как обычный текст. Ни поиска, ни
  команд, ни медиа, ни записи файлов в таком режиме быть не может.

Фронтенд шлёт `{"tools": bool, "search": bool}` в `POST /api/agent/stream`.
Клиенты без флага (Telegram, планировщик) работают с инструментами как раньше.

## Как агент получает инструменты и думает над шагами

Ход начинается со сцены «Понимаю запрос». Сразу после неё, если инструменты
нужны, появляются живые строки «Вспоминаю инструменты» и — для запросов про
MCP/GitHub/подключённые сервисы — «Вспоминаю MCP-серверы». Пока идёт эта
анимация, движок действительно собирает инструменты под текущий запрос
(`_build_tools()`), после чего строки меняются на «Вспомнил инструменты» /
«Вспомнил MCP-серверы» со списком реально подключённых тегов.

Каждый шаг (в том числе команда терминала) виден в таймлайне как
«Думает… → команда → Думал»: перед выполнением агент решает, что делать после
этого шага, а после выполнения осмысляет результат и выбирает следующий. Если
инструменты отключены, показывается «Инструменты не нужны» и шагов нет.

## Команды

В агентном режиме с доступным workspace модель получает инструкцию вызывать
функции единым Python gateway в блоке `terminal`. Обычные команды по-прежнему
выполняются существующей песочницей. Это не полный Bash и не изоляция ОС.

Примеры команд, которые генерирует сама модель:

```terminal
python3 -m novamind_cli tools
```

```terminal
python3 -m novamind_cli call web_search '{"query":"Python Flask repository bugs"}'
```

```terminal
python3 -m novamind_cli call web_open '{"url":"https://github.com/owner/repository"}'
```

```terminal
python3 -m novamind_cli mcp tools
```

```terminal
python3 -m novamind_cli mcp call '{"server_id":"github","tool":"search_repositories","arguments":{"query":"NovaMind"}}'
```

Имена MCP-сервера и инструмента берутся из доступного каталога. Любой инструмент
текущего исполнителя доступен через `python3 -m novamind_cli call <имя>
'<JSON>'`, например:

```terminal
python3 -m novamind_cli call file_read '{"path":"README.md"}'
```

Это не визуальная имитация CLI. В шаге агента команда передаётся реальному
request-scoped объекту инструмента, поэтому сохраняются Flask-идентичность,
capability-токен, подтверждение, отмена, события медиа и серверные MCP-секреты.
В ручном терминале та же команда идёт через общий `tool_registry` и возвращает
обычные `code/stdout/stderr`. Точная Python-команда показывается в таймлайне.

Один вызов на блок, аргументы — один JSON-объект в одинарных кавычках. Пайпы,
цепочки и перенаправления для gateway-вызовов не поддерживаются. При ошибке
модель получает реальный `[failure]`, меняет структуру JSON, имя поля, тип
аргумента или инструмент и пробует снова. Дословный неудачный вызов блокируется
защитой от циклов; лимиты шагов, дедлайн, отказ пользователя и политика
безопасности не обходятся.

Старые `nova search/read/help/tools` и `nova call` сохранены для совместимости.
Прямые блоки инструментов тоже продолжают разбираться, но новый системный
промпт обучает модель генерировать Python-команды.

## Документы

Модель может создать Python-скрипт существующим механизмом записи файлов и
выполнить `python3 report.py`. В зависимостях проекта уже есть `pypdf` для PDF,
`python-docx` для DOCX и `openpyxl` для XLSX. Отдельный конвертер в этой доработке
не добавляется. Действуют ограничения файловой системы workspace.

## Права, автономность и журнал

Агент сам выбирает следующие действия в рамках существующего цикла, бюджета
шагов, отмены и дедлайна. Вызов nova делегируется исходному инструменту **до**
проверки подтверждения: MCP сохраняет проверки администратора, операции записи
и внешние действия — существующие подтверждения. Журнал показывает фактический
целевой инструмент (поиск, открытие страницы, MCP, работа с файлами), обычные
команды — терминал. Время ожидания модели отображается существующим таймлайном,
а не заранее заданными «4 секунды» или внутренними рассуждениями.

Полный доступ к терминалу, снятие ограничений git push, новые GitHub credentials
и права администратора не добавляются. Поиск → clone → диагностика → исправление
→ тесты возможны лишь при наличии нужных команд и разрешений. Если публикация
недоступна в песочнице, агент должен вернуть diff, а не объявлять push успешным.
Строгий MCP-режим и запрет терминала у веб-исполнителя сохранены.

Проверка:

```sh
python -m pytest tests/test_terminal_commands.py tests/test_terminal_agent.py tests/test_agent_confirm.py tests/test_timeline.py -q
```
