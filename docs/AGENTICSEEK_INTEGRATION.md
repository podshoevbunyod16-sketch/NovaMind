# Интеграция AgenticSeek в NovaMind

Документ описывает замену самописного агентного слоя NovaMind на архитектуру
[AgenticSeek](https://github.com/Fosowl/agenticSeek) (`68aa632b`, 2026-10-22).
Он отвечает на четыре вопроса: **что теперь работает**, **как это устроено**,
**что пришлось изменить** и **что с лицензией**.

Состояние на момент написания: `pytest tests -q` → **472 passed, 0 failed**
(было 460 тестов на базовом коммите, часть переписана под новый протокол).

---

## 1. Коротко: что изменилось

| Было (самописный слой в `routes/agent.py`, 2 682 строки) | Стало |
|---|---|
| Один «умный» цикл: JSON-действия `{"action": "search"}`, эвристика сложности, ручная самопроверка | Пакет `agenticseek/` (≈5 400 строк): роутер → планировщик → агенты-специалисты, блок-протокол `` ```tag `` |
| Нет планирования: несколько инструментов подряд в одном ответе | `PlannerAgent` строит `{"plan": [...]}` из зависимых шагов и передаёт результаты дальше |
| Нет ролей: всё решалось набором if/elif | Роли `talk` / `files` / `code` / `web` + `planification`; у каждой свой промпт и свой набор инструментов |
| Ответ синтезировался вручную (`_synthesize`, `_fallback_answer`, «быстрый путь») | Ответ даёт агент; движок гарантирует, что пользователь его получит |
| Инструменты — функции внутри роута | Инструменты — объекты с тегом, риском и единым форматом `[success]`/`[failure]` |
| Почти нет персистентности шагов | `agent_runs` + `agent_run_steps` + `step_traces` для каждого хода |

Что **осталось прежним по смыслу** (это требование продукта, не архитектуры):
поиск и чтение страниц, медиа, память, навыки, MCP, задачи, расписание,
терминал и файлы в песочнице, подтверждение опасных действий, кнопка «Стоп»,
трасса шагов, учёт токенов, история чата, офлайн-режим без ключей и правило
«пользователь всегда получает ответ».

## 2. Лицензия — прочитать до распространения

AgenticSeek распространяется под **GNU GPLv3**. Пакет `agenticseek/` —
производная работа: файлы сохраняют уведомления об авторстве, полный текст
лицензии лежит в `agenticseek/LICENSE`, а раскладка «файл → источник» — в
`NOTICE.md` в корне репозитория.

Практическое следствие: `agenticseek/` импортируется в тот же процесс, что и
остальной NovaMind, поэтому при распространении собранного приложения на весь
продукт действуют требования GPLv3 (доступность исходников получателю,
сохранение уведомлений, запрет дополнительных ограничений). Внутреннее
использование обязательств не создаёт.

Если проект должен остаться на несовместимой с GPL лицензии, варианты такие:

1. заменить `agenticseek/` собственной реализацией — контракты и тесты ниже
   описывают всё, что нужно повторить;
2. вынести слой в отдельный процесс, распространяемый отдельно под GPLv3.

## 3. Архитектура

```
HTTP (Flask)                      agenticseek/
┌────────────────────────┐        ┌──────────────────────────────────────────┐
│ routes/agent.py        │        │ engine.AgentEngine                       │
│  авторизация, лимиты   │        │   ├─ Router  → роль / планировщик        │
│  история, NDJSON       │───────▶│   ├─ PlannerAgent ─┬─ CoderAgent         │
│  стоп, подтверждения   │ ctx    │   │                ├─ FileAgent          │
│  трасса, usage         │◀───────│   │                ├─ BrowserAgent       │
└────────────────────────┘ events │   │                └─ CasualAgent        │
                                  │   ├─ tools/  (bash, python, file_*, web_*,│
┌────────────────────────┐        │   │           nova-tools: MCP, медиа,     │
│ database.py            │◀──────▶│   │           память, задачи, расписание)│
│ agent_runs/steps/trace │        │   ├─ policy (риск, подтверждения)        │
└────────────────────────┘        │   └─ state.RunState (источники, медиа)   │
                                  └──────────────────────────────────────────┘
```

Ключевое разделение: **движок не импортирует Flask**. Всё, что нужно ходу,
передаётся функциями в `EngineContext` (поиск, чтение страницы, запуск
команд, генерация медиа, память, MCP), поэтому движок тестируется без HTTP,
а роут остаётся тонким фасадом (948 строк вместо 2 682).

### 3.1 Поток одного хода

1. `routes/agent.py::agent_stream` собирает контекст: провайдер и модель,
   историю из SQLite, блоки памяти и навыков, доступные инструменты,
   рабочий каталог песочницы, `run_id` и `cancel`.
2. `AgentEngine.stream()` запускает ход в рабочем потоке и отдаёт события по
   мере появления (NDJSON), поэтому «Стоп» и таймауты работают без разрыва
   соединения.
3. **Понимание запроса**: движок ставит первую сцену «Понимаю запрос» — это
   отдельный первый шаг хода, а не молчаливая подготовка.
4. **Динамическое получение инструментов**: после понимания приходят живые
   события `recall` — «Вспоминаю инструменты», а для запросов про MCP/GitHub
   ещё и «Вспоминаю MCP-серверы». Только после них `_build_agents()` вызывает
   `_build_tools()` и собирает реальные объекты инструментов под текущий
   запрос; событие `recall` с `done: true` закрывает анимацию списком
   подключённых тегов. При `tools: false` вместо этого приходит одна строка
   «Инструменты не нужны» — инструменты не создаются вообще.
5. `Router` выбирает исполнителя: короткое сообщение → `talk`; высокая
   сложность → планировщик; иначе роль по смыслу задачи.
6. Агент отвечает блоками `` ```tag … ``` ``; движок исполняет их по порядку,
   возвращает результат в память агента и повторяет, пока в ответе есть блок.
   **Каждый шаг обрамлён размышлением**: `think` с `phase: "before"` —
   «думаю, что сделать после этого шага», затем `tool`, затем `think` с
   `phase: "after"` и `done: true` — «осмыслил результат, выбираю следующий
   шаг». Так агент думает и до, и после каждого действия.
7. Перед финалом движок чистит ответ (`strip_unknown_blocks`, `finalize`),
   при пустом результате просит модель дать чистый ответ и, если и это не
   помогло, достаёт готовую цитату из черновика.
8. События `token` отдают ответ, `result` — итог хода, `done` — конец потока.
   Роут сохраняет ход в историю, считает токены и записывает трассу.

## 4. Протокол блоков

Модель действует блоками в ответе: один блок — одно действие; результат
возвращается как `[success] …` / `[failure] …` в следующем сообщении.

````
```bash
ls -la
```
````

| Тег | Что делает | Риск |
|---|---|---|
| `web_search` | поиск NovaMind, источники попадают в `state.sources` | safe |
| `web_open` | чтение страницы по полному URL | safe |
| `bash` | команда через песочницу `routes/terminal` | write/danger по таблице |
| `python` | код во временном файле, без интерактива | write |
| `file_finder` | поиск файла/содержимого в рабочем каталоге | safe |
| `file_edit` | замена уникального фрагмента (`{"path","old","new"}`) | write |
| `python:path` | создание **нового** файла | write |
| `mcp_call` | вызов инструмента подключённого MCP-сервера | по инструменту |
| `image` / `audio` / `video` | генерация медиа | write |
| `remember` / `forget` | долговременная память | write |
| `task` | задача с шагами | write |
| `schedule` | задание по расписанию (`{"prompt", "cron"\|"every"}`) | write |
| `skill_create` | сохранение навыка (`SKILL.md`) | write |
| `project_*` | чтение/поиск/дерево/патч проекта (кодинг-профиль) | read / write |

Правила, которые проверяются тестами:

* **неизвестный тег** не показывается пользователю: он вырезается из ответа,
  а агент получает ровно один повтор с `[failure] Инструмент «…» недоступен
  в этом запуске…`; в поток уходит шаг «Модель вызвала недоступный
  инструмент — действие не выполнено»;
* **повторный блок** с тем же содержимым не исполняется дважды;
* **блоки `bash`/`python`/`json` в тексте ответа** — это код в ответе, а не
  действие: они не исполняются (иначе ответ «вот пример команды» запускал бы
  команду);
* **payload передаётся дословно** (кроме первого аргумента там, где нужен
  путь/запрос — `first_argument()` срезает пустую первую строку);
* JSON-действия старого протокола (`{"action": "search"}`) не поддерживаются и
  никогда не попадают в чат.

### `recall` / `think` — видимое получение инструментов и мысли вокруг шагов

Фронтенд (`static/linux.js` → `createAssistantTurn`) обрабатывает два новых
события. `recall` с `done: false` рисует живую строку с дышащими точками
(«Вспоминаю инструменты», «Вспоминаю MCP-серверы»), а `done: true` для той же
`phase` превращает её в «Вспомнил …»; `phase: "ready"` закрывает все живые
строки, если поток оборвался. `think` с `done: false` создаёт строку
«Думает…» в блоке шагов, `done: true` меняет её на «Думал» и дописывает
результат осмысления. `finishTerm()` и `collapseStage()` закрывают незакрытые
строки сами, поэтому обрыв потока не оставляет вечную анимацию.

В трассу (`database.step_traces`) попадают только завершённые строки:
промежуточная анимация и «думаю перед шагом» в историю не пишутся.

### Длина ответа: почему он обрывался и как чинится

Раньше один ответ модели в агентном режиме был жёстко ограничен
`1200 * AGENTICSEEK_SPEED` токенов, тогда как обычный чат брал лимит из
настроек провайдера (8192–32768). Длинный ответ упёрся бы в этот потолок и
оборвался на полуслове — а `final_answer_text()` (фильтр «похоже на законченный
ответ») **отбрасывал весь текст**, потому что последнее слово оказалось
служебным. Дальше движок просил «чистый ответ» всё с тем же потолком, не
находил цитаты для `salvage_quoted_answer()` и отдавал одну строку
`Не удалось получить ответ…`. Воспроизводится тестом
`tests/test_answer_length.py`.

Что изменено:

1. `AGENT_MAX_TOKENS` (по умолчанию 4096, диапазон 1024–32768) — лимит одного
   ответа; роут дополнительно ограничивает его `max_tokens` выбранного
   провайдера (`EngineContext.max_tokens`). `AGENTICSEEK_SPEED` теперь может
   только укоротить бюджет, но не превысить лимит провайдера.
2. `repair_truncated_answer()` в `routes/agent.py` различает короткий обрывок
   (это утечка рассуждений — выбрасываем) и длинный ответ, оборванный на лимите
   (сохраняем завершённую часть до последнего полного предложения).
3. `AgentEngine._continue_answer()` просит модель дописать только недостающий
   хвост (`CONTINUE_ANSWER_SYSTEM`), убирает повтор через `_drop_overlap()` и
   склеивает части. Если продолжить не удалось — пользователь всё равно видит
   длинный текст, а не строку ошибки. Событие `step` «дописываю до конца»
   видно в чате.
4. `CLEAN_ANSWER_SYSTEM` и промпты `casual_agent`, `browser_agent`,
   `orchestrator_agent` больше не требуют «коротко»: они просят полный,
   законченный ответ. `_fallback_answer()` использует общий бюджет токенов.
5. `_looks_complete_answer()` маскирует fenced-блоки кода: непарные кавычки
   внутри кода больше не считаются обрывом. `strip_leaked_reasoning()` теперь
   убирает только абзацы-рассуждения, а не «хвост русских абзацев», поэтому
   код и английские примеры в конце ответа не отрезаются.
6. Офлайн-контур (`local_llm.py`) отвечает на вопросы про структуру проекта
   развёрнутым описанием каталогов — без ключа это лучшее, что доступно.

### `tools` — выключатель всех инструментов

`POST /api/agent/stream` принимает `tools` (и совместимый `search`). При
`tools: false` (кнопка «Автопоиск» выключена) `EngineContext.tools_allowed`
ложный: движок не вызывает `_build_tools()`, не подключает песочницу, поиск,
MCP и медиа, а `_run_direct()` делает **один** запрос к модели через
`CasualAgent` без инструментов. В потоке есть шаг «Автопоиск выключен…»,
`result.steps == 0`, `result.tools == []`. При `tools: true` агент работает
как обычно, в том числе выполняет шаги Linux-командами через `terminal`.
Клиенты без флага (Telegram, планировщик) получают инструменты по умолчанию.

`status` выставляется движком: `stopped` — сработала отмена, `error` — модель
или агент не смогли ответить, `ok` — иначе. Кнопка «Стоп» ничего не «глотает»:
недоделанный шаг не исполняется, частичный ответ сохраняется в историю.

## 6. Что сохранено из NovaMind и как это работает теперь

| Возможность | Как было | Как стало |
|---|---|---|
| Поиск (`nova_search`) | JSON-действие `search` | блок `` ```web_search ``; источники → `sources`, заметка в рабочую папку |
| Чтение страницы | `open` | `` ```web_open ``; текст оборачивается в `<untrusted tool="…">` |
| Медиа | ветка в роуте | прямой путь в движке (без модели) + инструменты `image/audio/video` для агента |
| Память | `remember`/`forget` в JSON | блоки `` ```remember ``` / `` ```forget ```, те же проверки секретов |
| MCP | `mcp_call` в старом цикле | инструмент `mcp_call`; `strict_mcp` оставляет только его |
| Задачи | `task`/`task_done` | инструмент `task`; закрытие — по ответу без блоков |
| Расписание | `{"action":"schedule"}` | блок `` ```schedule `` с `cron` или `every` |
| Навыки | `skill_create` | блок `` ```skill_create `` (SKILL.md) |
| Терминал и файлы | `run`/`read`/`write`/`ls`/`git` | `bash`, `python`, `file_finder`, `file_edit` поверх той же песочницы |
| Рабочая папка | общая с файловым менеджером | та же (`routes.terminal.WORKSPACE`, читается динамически) |
| Самопроверка ответа | второй запрос «проверь себя» | шаг «итог по результатам» в планировщике + фильтр утечек и восстановление ответа |
| Защита от утечки рассуждений | `_synthesize` + повтор | `finalize` → пусто → строгий повтор → спасение цитаты (см. §3.1, п. 5) |
| Учёт токенов | `usage_stats.record_turn` | без изменений по контракту, но работает и для нового движка |
| Трасса шагов | `step_traces` | `agent_runs` + `agent_run_steps`, а `step_traces` заполняется из событий |
| Кнопка «Стоп» | отмена флага в цикле | `POST /api/agent/stop {run_id}` + проверка между шагами и перед каждым инструментом |
| Офлайн без ключей | ветка в роуте | `agenticseek/offline.py` (реальный поиск, реальная попытка медиа, честный ответ) |

| `policy.needs_confirmation` | режим `AGENT_CONFIRM=off\|write\|danger` (по умолчанию `danger`); правила «разрешить всегда» ключуются `(tag, первые три слова)` и отзываются |
| `POST /api/agent/confirm`, `GET/DELETE /api/agent/permissions` | ответ на запрос и просмотр/сброс правил; таймаут по умолчанию 120 с читается на каждый запрос |

| `tools/sandbox.py` | единственный путь исполнения команд: движок не вызывает `subprocess` сам, а получает `runner` от `routes/terminal` |
| `routes/terminal` | белый список команд, запрет `;`/`&&`/`|`/подстановок, запрет выхода из `WORKSPACE`, таймауты, задачи с `git` |

| `<untrusted …>` | содержимое страниц и файлов помечается как данные, а не инструкции |
| лимиты | бюджет шагов (`AGENT_MAX_STEPS`), лимит вызовов модели за ход (`AGENTICSEEK_MAX_LLM_CALLS`), таймауты инструментов |

## 8. Персистентность

| Таблица | Что хранит |
|---|---|
| `chats`, `messages` | общая история чата и агента (агент пишет туда же, поэтому после перезагрузки помнит разговор) |
| `agent_runs` | один ход: `run_id`, `chat_id`, `goal`, `status`, `answer`, `error`, `steps`, время |
| `agent_run_steps` | шаги хода: `seq`, `tool`, `label`, `ok`, `output` |

упавший ход сохраняется со `status="error"` и текстом ошибки.

## 12. Ограничения и компромиссы

* **Роутер эвристический.** Классификатор upstream на `transformers` весит
  ~1.6 ГБ и не влезает в Termux; вместо него — детерминированные правила и
  опциональный один вызов модели (`AGENTICSEEK_ROUTER=llm`). Ошибка роутера
  стоит одного лишнего шага, не более: любой агент может ответить словами.
* **Планировщик дороже одиночного агента**: план — минимум один вызов модели
  плюс вызов на итог. Поэтому он включается только на сложных запросах.
* **Блок-протокол вместо нативного tool calling.** Нативный слой остался в
  `ai_providers` и `tool_registry`, но агент его не использует: на бесплатных
  моделях нативные вызовы приходят невалидными чаще, чем текстовые блоки.
* **Сеть браузера.** Без Selenium доступно только чтение страниц
  (`AGENTICSEEK_BROWSER=http`); агент честно сообщает об этом вместо
  выдуманного «я открыл сайт».
* **GPL.** См. §2: это не техническое, а юридическое ограничение, и оно
  действует на всё приложение при распространении.

## 13. Как откатиться

Ветка с интеграцией — отдельная; `main` не менялся. Откат — обычный
`git revert` мержа либо возврат к коммиту `ae02cb1`: старый движок жил целиком
в `routes/agent.py`, а новые таблицы (`agent_runs`, `agent_run_steps`)
создаются с `CREATE TABLE IF NOT EXISTS` и старому коду не мешают.
