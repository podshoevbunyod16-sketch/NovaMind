# 🫧 Liquid Glass · NovaMind

Полное оформление интерфейса «живым стеклом» + живой поиск и рассуждения.

---

## 1. Что изменилось визуально

Единая дизайн-система в **`static/liquid-glass.css`** (подключается первой на всех
страницах), поверх неё — стилевые слои страниц:

| Страница | Файл |
|---|---|
| Чат | `static/style.css` |
| Настройки | `static/settings.css` |
| Вход / регистрация | инлайн-стили в `templates/auth.html` |
| Админ-панель | инлайн-стили в `templates/admin.html` |
| Composio | `templates/composio.html` |

Что входит в систему:

- **Живой фон** — три слоя: дрейфующие aurora-пятна (`body::before`), медленно
  вращающийся спекулярный блик (`body::after`), зерно + виньетка
  (`.lg-grain`, `.lg-vignette`).
- **Матовое стекло** — `backdrop-filter: blur() saturate()`, полупрозрачные
  градиенты, светящаяся кромка сверху (`--glass-inset`), мягкие тени.
- **Одна тема — `aurora`.** Палитра зафиксирована: кнопки 🎭 в чате и
  настройках, точки на странице входа и админ-панель применяют только её.
  Значение по умолчанию — `localStorage: nova_theme = aurora`.
- **Микроанимации** — пружинные нажатия кнопок, бегущий блик, всплывающие тосты,
  появление сообщений, «дыхание» логотипа и аватара.
- **Доступность** — `prefers-reduced-motion` и кнопка «✨ Анимации»
  (`data-motion="calm"`) отключают фоновую хореографию.
- **Fallback** — если браузер не поддерживает `backdrop-filter`, поверхности
  становятся плотными, интерфейс не ломается.

### Компоновка чата: один ползунок и ненавязчивый сайдбар

- **Один ползунок на всё окно.** Прокручивается документ, а не отдельные
  панели: у `.chat-container`, `.sidebar-body` и списка истории своего
  `overflow` нет. Шапка (`.topbar`) и поле ввода (`.input-area`) — липкие
  (`position: sticky`), поэтому всегда на виду, а переписка уезжает под них.
- **Сайдбар по умолчанию скрыт.** На широком экране класс `nav-off` у `.app`
  убирает панель (`.app.nav-off .sidebar`), освобождая всю ширину под чат.
  Кнопка-бургер в шапке (и `Ctrl+B`) открывает её, выбор запоминается в
  `localStorage` (`nova_nav_open`). На узких экранах работает прежний
  выдвижной ящик со свайпом.
- **Активный режим всегда виден и снимается.** Клик по «Погода», «Курс валют»,
  «Код» и т.п. включает режим и показывает плашку `.mode-active` с крестиком;
  повторный клик по тому же пункту или «✖» в палитре команд (`Ctrl+K`) его
  выключают. «Новый чат» и «Очистить чат» снимают режим и медиа-модель.
- **Длинные имена моделей обрезаются.** `shortModelName()` / `setShortText()`
  в `app.js` оставляют первые два слова (или первые буквы) + многоточие, а
  полное название уходит в `title`. В шапке `#statusText` дополнительно
  ограничен `max-width` с `text-overflow: ellipsis`, поэтому кнопки темы,
  настроек и очистки не выталкиваются за экран.

## 2. Поиск в интернете — как это выглядит

Кнопка **«Поиск в интернете»** в панели ввода. Сценарий в пузыре ИИ:

1. Пузырь появляется **пустым**.
2. Включается **анимированная сцена**: радарный луч, три орбиты с частицами,
   пульсирующее ядро, скан-линия, уходящая сетка.
3. Через полсекунды проявляется подпись **«Поищу в интернете»** и таймер.
4. Под сценой бегут **реальные шаги**: какой бэкенд пробовали, сколько
   результатов нашли, какие страницы читаем.
5. Найденные **источники** приходят отдельным событием и рисуются в пузыре.
6. С первым токеном ответа **сцена схлопывается** (анимация высоты и прозрачности).
7. Ответ **печатается по токенам**.
8. В самом **низу пузыря** остаётся блок «🔗 Источники · N» — сворачиваемый
   список с favicon, заголовком, доменом и ссылкой.
9. Под пузырем — мета (модель, время) и действия: копировать / озвучить / заново.

### Найденные данные всегда доезжают до пользователя

`routes/search.py` не оставляет пустой пузырь: если модель не отвечает,
включаются запасные шаги.

| Шаг | Что происходит | Что видит пользователь |
|---|---|---|
| 1. Поток | `chat_stream` с `ANSWER_TIMEOUT` (по умолчанию 180 с) | ответ печатается по токенам |
| 2. Обрыв | сеть/провайдер рвут соединение | уже полученные токены остаются, шаг «🔁 Поток прерван… повторяю запрос» |
| 3. Без стрима | тот же запрос через `chat_completion` | цельный ответ приходит в `result.reply` |
| 4. Модель мертва | ответ не получен ни одним путём | `_fallback_answer()`: заголовки, домены, ссылки и выдержки из найденных источников |

Обрыв соединения посреди потока больше не рвёт генератор: `ai_providers._raw_stream`
ловит исключение и отдаёт `error` вместе с уже накопленными токенами.
Если источники нашлись, а ответ модели не пришёл вовсе, фронтенд честно пишет
об этом в пузыре и оставляет ссылки — молчаливый ответ «по памяти» вводил бы
в заблуждение.

### События потока `POST /api/auto_search_stream`

Ответ — `application/x-ndjson`, по одному JSON-объекту на строку:

```jsonc
{"type":"stage","scene":"search","title":"Поищу в интернете","text":"…"}
{"type":"step","icon":"🌐","text":"Ищу через searxng…"}
{"type":"sources","sources":[{"title":"…","url":"https://…","host":"…"}]}
{"type":"stage","scene":"write","title":"Собираю ответ"}
{"type":"reasoning","token":"…"}          // ход мыслей, если включён
{"type":"token","token":"…"}              // печатающийся ответ
{"type":"result","reply":"…","searched":true,"sources":[…],"model":"…","trace":[…]}
{"type":"done","searched":true}
```

### Поисковые бэкенды

`apilayer → serper → searxng → ddg → ddg_lite → wiki` — перебираются до первой
непустой выдачи, по каждому остаётся запись в `trace` (время, ошибка).
Настраивается в `.env`:

```env
SEARCH_BACKENDS=searxng,ddg,ddg_lite,wiki
SEARXNG_INSTANCES=http://127.0.0.1:8888,https://searx.be
WIKI_API_BASES=https://ru.wikipedia.org/w/api.php
SEARCH_TIMEOUT=9
READER_TIMEOUT=10
SEARCH_MAX_PAGES=3
SEARCH_QUERY_TIMEOUT=10
ANSWER_TIMEOUT=180
```

Диагностика: **`GET /api/search/health?refresh=1`** (кеш 60 секунд) и панель
«Поиск в интернете» на странице настроек. Точка-индикатор рядом с кнопкой
поиска в чате показывает состояние бэкендов.

## 3. Рассуждения

Кнопка **«Рассуждение»**. В пузыре появляется сворачиваемая панель
«🧠 Рассуждение» с курсивным текстом хода мыслей; пока модель думает, панель
раскрыта, после ответа сворачивается.

- `gpt-oss-*` на Groq отдают нативный `reasoning` — он идёт в поток как есть.
- Для моделей без нативного reasoning выполняется короткий предварительный
  «план рассуждений», который печатается в ту же панель.
- Если модель ничего не отдала — панель честно сообщает об этом.

## 4. Единый слой ИИ и офлайн-модель

`ai_providers.chat_completion()` / `chat_stream()` — одна точка входа для всех
провайдеров (Groq, Gemini, OpenRouter, Cerebras, OpenAI-compatible/llama.cpp,
Pollinations, офлайн-модель). Раньше каждый маршрут дёргал транспорт вручную,
из-за чего, например, поиск ломался на Gemini (в URL провайдера плейсхолдер
`{model}`).

**`local_llm.py`** — встроенная офлайн-модель `nova-local-1`:

- работает без интернета и без ключей, чат не остаётся без ответа;
- не ищет в сети и честно об этом пишет;
- выбирается автоматически, если ни один облачный провайдер не подключён;
- доступна в настройках как провайдер «Локальная демо-модель».

Состояние движка: **`GET /api/ai/status`** → провайдер, модель, `offline`,
состояние поиска. Показывается в топбаре чата.

## 5. Бонусы

- **Ctrl+K / ⌘K** — командная панель: режимы, переключатели, команды `/help`,
  погода, валюты, Википедия, код, изображения.
- **Стоп-генерации** — кнопка отправки превращается в «стоп» и останавливает
  поток даже при пустом поле ввода; `Enter` во время генерации — тоже стоп.
  Остановка гасит `AbortController` текущего запроса (в том числе поиска).
- **Действия под ответом** — копировать, озвучить (Web Speech), ответить заново.
- **Источники сохраняются в истории** — при возврате к диалогу ссылки и
  рассуждения отрисовываются снова.
- **Тосты вместо `alert`** — стеклянный стек уведомлений под шапкой, чтобы не
  перекрывать прилипшее поле ввода.
- **Индикатор состояния** — точка в топбаре: модель, офлайн-режим, поиск.
- **Офлайн/онлайн** — при восстановлении соединения статусы обновляются сами.
- **Горячие клавиши** — `Enter` отправить, `Shift+Enter` перенос, `Ctrl+B`
  показать/скрыть сайдбар, `Esc` закрыть панель/модалку, `Ctrl+J` панель Linux,
  `Ctrl+Shift+A` агентный режим, `?` шпаргалка, `↑`/`↓` история в терминале.

## 5.1 Маленький Linux, агент и задачи

Одна идея вместо набора разрозненных кнопок: сначала появляется рабочее
окружение, а остальные функции работают поверх него.

**Панель (`Ctrl+J`)** — стеклянная выдвижная панель справа, четыре вкладки:

- *Терминал* — моноширинный вывод, приглашение `$`, быстрые чипы (`ls -la`,
  `python3 hello.py`, `git status`), история по `↑`/`↓`, `Ctrl+L` очищает.
- *Файлы* — дерево рабочей папки с размерами, просмотр содержимого, «В чат»
  и «В терминал».
- *Git* — ветка, «чисто/изменений», список файлов с флагами, последний коммит;
  если репозитория нет — кнопка `git init`.
- *Поиск* — интернет и поиск по песочнице одним переключателем. У каждого
  источника кнопки: «В чат», «В задачу», «Сохранить» (в рабочую папку),
  «Читать» (зачитывает страницу в терминал).
- *Задачи* — список дел: добавить, переключить статус кликом по кружку, удалить;
  у задач агента видны шаги с логом команд.

**Агентный режим** (`Ctrl+Shift+A` или кнопка в шапке) — сообщение уходит не
модели напрямую, а в ограниченный цикл: план → действия в песочнице → задача →
ответ. В ответе видно каждый шаг, вывод каждой команды (сворачиваемый блок) и
карточку заведённой задачи; в подписи — число шагов.

**Поиск как функция окружения**

Свежие данные берутся не отдельной кнопкой, а самой песочницей:

| Где | Как |
|---|---|
| Терминал | `nova search <запрос>`, `nova search <запрос> --save`, `nova read <url>` |
| Панель | вкладка «Поиск»: интернет ⇄ по песочнице (тот же `grep`) |
| Агент | `{"action":"search"}` и `{"action":"open"}`, находки падают в задачу |
| Блок кода | кнопка «🔎 Аналог» — запрос строится по языку и имени функции |

Бэкенды общие с поиском в чате, поэтому «терминал» и «чат» видят одно и то же.

**Бонусы для программиста**

- У каждого блока кода — «Объясни», «Тесты», «Оптимизируй», «🔎 Аналог»,
  копирование и «В терминал» (кладёт код в песочницу). В агентном режиме
  «Объясни» сразу уходит агенту, а не в поле ввода.
- Шпаргалка по `?` — все горячие клавиши на одном экране.
- `Ctrl+J` — панель, `Ctrl+Shift+A` — агент, `Esc` — закрыть панель, затем
  снять агентный режим.

**Границы (это сервер, а не песочница ОС)**

| Что | Как защищаемся |
|---|---|
| Кто входит | только администратор: `session['admin_logged_in']` |
| Включено ли | `TERMINAL_ENABLED=1` / `AGENT_ENABLED=1` в `.env`, по умолчанию выключено |
| Команды | белый список, запуск без shell, `|`, `>`, `&&`, `sudo` запрещены |
| Файлы | любой путь приводится внутрь `workspace/`, выход наружу — ошибка |
| Ресурсы | таймаут на команду, обрезка вывода, не больше двух команд одновременно |
| Агент | `AGENT_MAX_STEPS` шагов, общий `AGENT_TIMEOUT`, лимит на шаг |

## 6. Как проверить

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt

# backend: поиск, единый слой ИИ, страницы (локальные mock-серверы, сеть не нужна)
python -m pytest tests/test_search_and_ai.py -q

# backend: песочница, терминал, задачи и агентный цикл (24 проверки)
python -m pytest tests/test_terminal_agent.py -q

# backend: поиск через песочницу — терминал, эндпоинты, агент (17 проверок)
python -m pytest tests/test_search_linux.py -q

# всё вместе
python -m pytest -q

# frontend: настоящие index.html, app.js и linux.js в jsdom
# (109 проверок: поиск, стоп, режимы, панель Linux, терминал, задачи, агент,
#  поиск через песочницу, страницы)
npm install jsdom
python app.py &                     # поднять сервер на :5000
node tests/frontend/smoke.mjs http://127.0.0.1:5000
```
