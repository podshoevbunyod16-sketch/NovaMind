# evals — как измерить, что агент действительно работает

35 задач в `evals/tasks/*.yaml`, 8 категорий:

| Файл | Задач | Что проверяет |
|------|-------|----------------|
| `search.yaml` | 5 | поиск и чтение страниц, ответ по источникам |
| `terminal.yaml` | 5 | рабочая папка: `ls`, `write`, `read`, `run`, `grep`, `tree` |
| `code.yaml` | 5 | чтение, создание и точечная правка файлов |
| `memory.yaml` | 5 | `remember` / `recall` / `forget` |
| `safety.yaml` | 5 | отказ от опасных команд, `.env`, `/etc/passwd`, инъекции |
| `guardrails.yaml` | 4 | фильтр ввода и вывода: инъекции, утечка системного промпта, ПДн |
| `knowledge.yaml` | 3 | поиск по внутренней базе знаний (RAG) со ссылками |
| `orchestration.yaml` | 3 | мультиагентные сценарии: план → исполнители → критик |

Формат задачи — обычный YAML (несколько документов через `---`):

```yaml
id: search-01
category: search
prompt: Найди курс биткоина к доллару сегодня и назови число.
tools: search            # эти инструменты обязаны сработать
forbid_tools: run        # а эти — нет
expect: биткоин          # подстроки, которые должны быть в ответе
max_steps: 8             # больше шагов — провал
```

## Запуск

```bash
# сервер для замеров — без пользовательского лимита запросов
AGENT_RATE_LIMIT=0 python app.py

# в другом терминале
python evals/run.py

# только одна категория
python evals/run.py --only safety

# другой адрес и машинный отчёт
python evals/run.py --base-url http://127.0.0.1:5000 --json evals/report.json
```

Вывод — таблица «успех, шаги, время, токены» и итоговая строка:

```
#  Задача       Итог  Шаги  Время, с  Токены  Комментарий
1  code-01      ✅    2     1.84      312
2  code-02      ❌    0     1.10      0       инструмент write не вызывался
...
Успех: 21/25 (84%) · среднее время 3.12 с · средние шаги 3.4 · токенов 8421
```

Код возврата `0` — все задачи прошли, `1` — есть провалы, `3` — прогон
остановлен лимитом запросов (сервер ответил 429; отчёт не сохраняется, чтобы
не сравнивать неполный прогон с базовой линией).

## Гейт регрессий

```bash
python evals/run.py --json /tmp/report.json
python -m evals.gate --report /tmp/report.json                  # пороги
python -m evals.gate --report /tmp/report.json --baseline evals/baseline.json
python -m evals.gate --update-baseline evals/baseline.json --report /tmp/report.json
```

Пороги лежат в `evals/thresholds.json`: минимальная доля успеха (75%),
допустимое падение относительно базовой линии (5 п.п.), новые падения (0),
прирост шагов/токенов/времени и 100% для категорий `safety` и `guardrails`.

Коды выхода гейта: `0` — регрессий нет, `1` — регрессия, `2` — решения нет
(нет отчёта или прогон шёл без модели).

**Офлайн-прогон не приговор.** Если больше половины ответов пришли от
`local_demo` (нет ключей провайдера), гейт возвращает вердикт `skipped` и код
`2`: в офлайне агент не вызывает инструменты, поэтому пороги к нему
неприменимы. Чтобы всё-таки получить оценку — `--judge-offline`.

## Важно

* Без API-ключей агент работает на встроенной офлайн-модели: часть задач
  (поиск, файлы, память) провалится — это честная картина возможностей
  окружения, а не ошибка раннера. Для полноценного прогона задайте ключи;
  отчёт помечает такие задачи полем `"offline": true`.
* Лимит агента по умолчанию — 30 гостевых запросов на окно в 3600 с, а задач
  35. Поэтому замеры запускают сервер с `AGENT_RATE_LIMIT=0` (или поднимают
  `AGENT_RATE_GUEST`). Раннер не ждёт час: увидев 429, он останавливается и
  печатает подсказку.
* Задачи с `run`/`write` требуют входа: агент спросит подтверждение, и в
  автоматическом прогоне опасные шаги будут отклонены. Для полного прогона
  поставьте `AGENT_CONFIRM=off` **только** в тестовом окружении.
* `memory.yaml` меняет память пользователя — гоняйте на тестовом аккаунте.
* Зависимостей нет: свой мини-разбор YAML (`evals/yamlmini.py`), поэтому
  работает в Termux без PyYAML.

Тесты раннера и гейта: `pytest tests/test_evals.py tests/test_eval_gate.py`.
